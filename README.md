# ContactRegistry — контактная книга

Переносимое приложение для Windows 10/11 x64. Люди, организации и ИП, реквизиты для договоров, телефоны, почта, теги, заметки и связи. Русский интерфейс, светлая и тёмная темы, поиск по контактам, ИНН и нормализованным номерам телефонов. Данные хранятся в SQLite; интернет нужен только для проверки и загрузки обновлений.

## Запуск на Windows

1. Скачайте `ContactRegistry-0.1.0-win-x64.zip` из Releases или артефактов GitHub Actions.
2. Распакуйте **всю папку** в доступное для записи место, например `Документы\ContactRegistry`. Не запускайте EXE прямо из ZIP и не используйте `Program Files`.
3. Запустите `ContactRegistry.exe`. Установка, Node.js и права администратора не нужны.
4. Добавьте человека или организацию. Теги вводятся через запятую, телефоны и почта — по одному на строку. В карточке есть копирование отдельных значений и всех реквизитов.
5. Связи добавляются из карточки: выберите другой контакт и укажите роль, например «Директор». Связь отображается с обеих сторон.

ZIP пока не подписан сертификатом Windows: система может показать предупреждение о неизвестном издателе. Корпоративная политика может запрещать запуск неподписанных приложений; права администратора приложение не запрашивает.

## Одна база на нескольких ПК

Рекомендуется держать **свою копию программы на каждом ПК**, а общую базу — на сетевом диске. По умолчанию база находится в `ContactRegistryData\contacts.sqlite` рядом с EXE. Настройки выбранной папки и темы сохраняются в профиле текущего пользователя Windows.

В настройках на каждом ПК выберите одну и ту же общую папку, например `\\server\contacts`. Первый компьютер создаст в ней базу, остальные подключат её. Нужны обычные права чтения, создания, переименования и удаления файлов в этой папке. При смене папки существующие данные **не переносятся и не объединяются**. Для переноса создайте резервную копию с именем `contacts.sqlite` в пустой целевой папке и подключите её.

Приложение не держит SQLite открытой на сетевом диске. Оно читает снимок в память, на время записи создаёт общую папку блокировки, перечитывает последнюю версию и заменяет файл временным после сброса записи на диск. Предыдущая версия сохраняется как `contacts.sqlite.previous`. Одновременная запись отклоняется; устаревшая правка карточки не перезапишет чужие изменения. Список перечитывается каждые 12 секунд, пока окно активно и форма редактирования закрыта; есть кнопка обновления.

Используйте SMB-сервер с корректной атомарной операцией создания каталога и переименования файлов. OneDrive/Dropbox и другие папки с отложенной синхронизацией не подходят для совместной записи. При потере сети приложение сообщает об ошибке и не переключается на другую базу. Не используйте сторонние SQLite-редакторы одновременно с приложением.

После аварийного завершения может остаться `.contactregistry-write-lock`. Сначала закройте приложение **на всех ПК**, убедитесь, что никто не пишет в базу, затем удалите эту папку. Автоматически приложение блокировку не снимает. Сетевые файловые системы различаются: перед рабочим использованием проверьте два ПК на вашем сервере. Полная устойчивость к сбоям сети/питания без серверной БД не гарантируется.

## Резервные копии

В настройках нажмите «Сохранить резервную копию». Копия содержит контакты, теги, заметки и связи. Не перезаписывайте единственную хорошую копию: используйте даты в именах. Автоматический `.previous` сохраняет только предыдущую запись, поэтому не заменяет отдельные резервные копии.

Для восстановления закройте приложение на всех ПК, сохраните текущий файл отдельно, скопируйте нужную копию под именем `contacts.sqlite` в отдельную папку и подключите эту папку в настройках. Либо замените файл в общей папке при закрытых приложениях. Шифрования и пароля приложения нет; защищайте доступ к сетевой папке средствами Windows.

## Обновления без api.github.com

При запуске приложение проверяет `https://github.com/Admutium/ContactRegistry/releases/latest/download/update.json`. Проверку можно отключить или выполнить вручную в настройках. Обычная работа полностью автономна. Контакты не отправляются на GitHub; сетевой запрос раскрывает серверу обычные сведения соединения, включая IP.

Установка начинается только после подтверждения. Загружается ZIP соответствующей версии из этого репозитория; проверяется SHA-256 из манифеста, затем пользовательский PowerShell-процесс дожидается закрытия приложения, распаковывает файлы и перезапускает EXE. База в `ContactRegistryData` и настройки не входят в архив обновления. Если папка программы общая, перед обновлением закройте её на всех ПК; лучше обновлять локальную копию на каждом ПК отдельно.

SHA-256 проверяет целостность относительно манифеста по HTTPS; это не цифровая подпись издателя. Защищайте доступ к репозиторию и публикации релизов. Для корпоративного распространения желательно добавить подпись кода. Если PowerShell запрещён политикой ПК или обновление прервалось, закройте приложение и распакуйте новую версию вручную в папку программы, сохранив `ContactRegistryData`. Приложение не обходит корпоративные ограничения запуска. До публикации первого релиза проверка сообщает, что обновлений пока нет.

## Разработка и сборка

Требуется Node.js 24 и npm. Используйте существующий checkout, отдельный worktree не нужен.

```sh
npm ci
npm test
npm start
npm run build:win
node scripts/release-manifest.cjs
```

Результат: `dist/ContactRegistry-0.1.0-win-x64.zip`; распакованная папка — `dist/win-unpacked`. Зависимости фиксируются `package-lock.json`. Electron и инструменты сборки нужны только разработчику. На Linux `npm start` требует графическую сессию и системные библиотеки Electron; Windows-архив можно собрать без запуска Windows. Тесты хранилища не требуют GUI.

`src/store.cjs` — SQLite, валидация и координация записи; `main.cjs` — файловые операции и ограниченный IPC; `preload.cjs` — мост; `renderer.js`, `index.html`, `style.css` — интерфейс; `update.cjs` — проверка и загрузка релизов. Renderer не имеет доступа к Node.js, произвольной сети и новым окнам; включены sandbox, context isolation и CSP. Внешних шрифтов, аналитики и CDN нет.

Дополнительная проверка интерфейса: `node scripts/ui-smoke.cjs` после `npm ci` и установки Chromium (`npx playwright install chromium`; на Linux по умолчанию используется `/usr/bin/chromium`, `CHROMIUM_PATH` задаёт другой путь). Она использует настоящий Store через тестовый мост: создание человека и организации, реквизиты, связь, поиск телефона, изменение карточки, конфликт второго ПК, смена темы и удаление. Это не проверка Windows EXE.

## Выпуск новой версии

Workflow `.github/workflows/windows.yml` собирает ZIP на Windows и прикладывает его как артефакт при ручном запуске. Для публичного релиза обновите `version` в `package.json` и lockfile, создайте соответствующий тег `vX.Y.Z` и отправьте его в GitHub. Workflow проверит совпадение версии и тега, запустит тесты, соберёт ZIP и `update.json`, опубликует GitHub Release через токен Actions. Право публикации ограничено job сборки; приложение токен не использует.

Перед первым рабочим релизом вручную проверьте Windows 10/11 без администратора, общий SMB-диск с двух ПК и обновление с предыдущей версии с сохранением базы. Сборка в Linux и тесты на локальной файловой системе этих проверок не заменяют.
